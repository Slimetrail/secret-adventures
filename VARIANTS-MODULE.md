## Per-save value
- `live.vseed`: uint32 from `crypto.getRandomValues` (fallback `Math.random`), set at new game. Separate from `live.seed` (combat).
- Old saves: `ensureVseed()` in party.js (boot load, Load, death restore) gives one value once and writes it to the active slot.
- `live.vpools` (shuffle state) and `live.vpick` (variant picks) are plain save fields, so Save / Load / Continue / slot copy keep them.
- Streams: `mulberry32(hash(vseed + "|" + purpose))`. Purposes: `pool:<key>#<cycle>`, `add:<key>...`, `variant:<scene id>`.

## Shuffled pools (work today with the existing lines)
Each pool key keeps `{o: order of ids, c: cursor, n: cycle, l: last id}`. The caller's gates choose what is eligible
(zone, companion present, unlock, unseen, meal / hurt gates); the order only chooses which eligible line comes first.
At the end of a cycle a new order is shuffled; the new cycle never starts with the last line of the old one.
Keys: `seq:<context>` / `seq-g:<context>` (gated talks first, as before) / `seq-r:<context>` (repeat mode) for batch 1-14 talks;
`pool:<pool>` (unseen first) and `pool-r:<pool>` (repeats) for PACKAGE_POOLS; `story:camp|tavern|stay:<tone or t>` for story-data
talks (same rules as story.js seenFirst); `fight:who` + `fight:start:<code>:<tone>` for fight start lines; `z4:<slot>:<mix>`
and `z4g:<slot>` for zone 4 banter (tiers exact mix -> smaller mixes -> hero, then generic, so no mix goes silent).
Static: sick-dad intro (H.created), the 3 endings, zone 5 / Dad pieces, letter, boss.

## Variants: data shape and ids
Today's lines are always the base, id `<scene id>-v1`, read from the locked data files. Never list a `-v1` entry (it is ignored).
The pick (v1 / v2 / v3 ...) is made once per save from the value + scene id, and stored in `live.vpick[<scene id>]`; a stored pick
is kept even if more variants are added later.

| scene id | where | shape of each entry |
|---|---|---|
| `join-mira`, `join-sorrel` | STORY.join[0] / [1] (Tavern 1 / 2) | `{id, place, lines}` |
| `join-brunn-save`, `join-brunn-died` | pool rows 82+84 / 83+85 (Tavern 4) | `{id, place, lines}` (played calm) |
| `wall-z1-01` .. `wall-z1-03` | STORY.wall[1][n] | `{id, place, solo:{place,lines}, party:{place,lines}, journal}` |
| `wall-z2-01` .. `wall-z2-04` | STORY.wall[2][n] | `{id, place, lines, journal}` |
| `ar1-01` .. `ar2-04` | PACKAGE_STORY.art AR<z>-<nn>-<suffix> | `{id:"ar1-01-v2", pieces:{h,m,s,bs,br:{id,place,lines,journal?}}}` |

- lines: `[[speaker, emotion, text], ...]`; speaker `H Q S A N`; `{H} {Q} {S} {A}` are filled at play time; default names only
  (companion-display.js swaps in Alden).
- Zone 1 walls: solo form when the party is hero-only, party form otherwise (one stored pick).
- Absent companions: their lines drop (walls / presence talks are PARTIAL_OK; joins filter them in code).
- Presence talks: one pick per room; the piece is chosen by the suffix the game already picks (H M S BS BR). A picked piece with
  no spoken lines (the 8 zone 2 `-h-` pieces, journal-only and unreachable because Mira is always there) or a missing piece plays v1.
- `journal`: a hero journal note, never spoken. Queued when that variant's piece plays (`story.vjournal`) and written into
  `story.journalSplit.pages` (`id "VJ-<piece id>"`, kind `art-rooms-remembered`) at the next camp hook.
- PLACE tags: `PLACE: secret-adventures / <scene> / dialogue / text / <piece id>` as in the approved file, e.g.
  `PLACE: secret-adventures / tavern-1-join / dialogue / text / join-mira-v2`, `.../zone1-01-rat-entrance/.../wall-z1-01-v2-party`.

## Adding more variants
1. Approved md in the same format -> `python3 tools/make-variants-z1z2.py <file.md> dialogue-variants.js` (it refuses v1, bad ids,
   missing PLACE, a zone 1 wall without both forms). New scene kinds need a hook in variety.js first.
2. Bump `dialogue-variants.js?v=` in index.html and sw.js, and the sw.js VER.
3. `node --test tests/t2675u_variety_test.js` (compares every installed line to the md), then the browser smoke.
